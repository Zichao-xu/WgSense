# 个人用常驻服务候选实现（2026-09-25）

用户已明确接受个人使用下的本机 root API 安全取舍。本轮因此继续实现服务可靠性，不把完整权限拆分作为前置条件。此前 `authorization-review-2026-09-25.md` 保留为旧候选审阅记录；本文件描述随后实现的当前候选。

## 已实现的行为

- 全 App 共用一个安装协调器，App 初始化检查，不依赖主窗口是否打开。取消只结束本次自动尝试，明确的用户操作可以重试，没有永久 attempted 标记。不同操作同时到达时会分别复核身份和版本，断开旧服务的宽松检查不能授权新连接。
- 首次授权仅提交独立的 launchd 安装任务。安装器先复制并校验全部文件，再检查现有服务、备份文件及所有权、停止旧服务、加载新服务、核对实际 helper 的协议/登录用户/SHA256，最后提交安装记录。
- 首次安装和旧版迁移清除旧 VPN/守护自动连接意图；新进程在事务提交前不运行网络策略。打开 App、安装 helper 与用户明确开启 VPN 是不同动作。
- 正常重开 App 复用同一服务；Mac 重启或 daemon 退出后由 launchd KeepAlive 拉起。运行中的 helper 的 SHA256 与 App 内嵌 helper 一致才允许新的连接操作。
- 已支持新版协议的 root helper 可提交独立安装任务升级自己，无需再调用管理员授权。隧道未明确断开时延后升级；确认断开与冻结新连接/巡检在同一操作锁内完成。停止旧版连接仍可执行，不会陷入“必须先升级才能断开”的循环。
- 升级提交后旧 daemon 若在 HTTP 应答前退出，客户端会核对新服务身份或新安装任务回执，避免将已提交的升级误报为失败。
- 系统服务重启使用本地受控 API，客户端观察新的 PID 和相同版本就绪；App 退出不停止网络服务。
- 安装失败恢复旧文件、权限、配置和服务，并确认旧服务实际就绪。恢复未完成时保留事务与重试任务；事务提交与结果写入之间崩溃，重试不会重复安装或重启。
- 卸载共用安装锁，拒绝与安装/恢复并发，只操作 WgSense 服务和已知安装文件，并清除安装记录。用户 profile、设置及收发文件保留；以后重装按首次安装处理。
- 全部退出入口共用一次关闭过程；policy 进入永久退出状态后，已排队的连接、恢复和巡检都不能再次建立隧道。
- 手动开启 VPN 会解除此前的暂停标记，避免 daemon 重启后持久连接意图仍为开启、却被旧暂停标记永久阻止恢复。

## 官方 WireGuard 共存

每次创建 WgSense 隧道前，先只读检查 macOS 注册的系统 VPN。Connected、Connecting、Disconnecting、Reasserting 均拒绝新的 WgSense 接管；该检查位于旧状态清理和 DNS 恢复之前。普通系统 utun 不被当成 VPN。当前官方 WireGuard 名为 `WgSense-default`，名称不会使其被排除。

此检测针对 SystemConfiguration 中的系统 VPN，不覆盖没有注册的任意用户态隧道，也不能阻止用户在 WgSense 已建立后另外开启 VPN。维护清理已去掉通用 pkill、硬编码路由删除和 DNS 清空，只请求在线、已识别的 WgSense 清理它自己的状态。

## 本地验证

- Go 全量测试与 API/service/policy/tunnel/daemon 竞态测试。
- 安装事务测试使用临时文件、假的 launchctl/子进程和 loopback HTTP，覆盖首次清意图、升级保留设置、启动/身份失败回滚、原 UID/GID 恢复、未知端口、并发锁、恢复重试、幂等提交、旧服务迟迟未就绪及卸载。
- API 测试验证安装未提交时拒绝网络命令、HTTP 方法/返回格式、旧服务未断开时不提交升级、提交期间保持维护冻结，以及失败后解除冻结。
- policy 并发测试验证清理后不重连、维护期间不重连、维护结束恢复原策略、手动 VPN 意图可在新引擎实例中恢复。
- 外部 VPN 检测的状态解析、只读命令与时间限制测试；上一轮真实 wireguard-go 内存 TUN/loopback UDP 失败恢复测试保留。
- macOS Debug App 构建、脚本语法和差异格式检查。

## 尚未进行的验收

没有安装或打开候选 App，没有提交真实 launchd 任务，没有操作当前官方 WireGuard、DNS、路由或服务器，也没有发布。因此“管理员只输入一次”、实际 Mac 冷重启、真实 launchd 更新/回滚、旧临时服务移交和联网恢复仍是待验收结果，不能由隔离测试代替。

完整场景见 [首次授权验收矩阵](authorization-acceptance-matrix-2026-09-25.md)。现有安装 App 仍为旧 0.3.10 build 20；候选代码已实现上述路径，但只有完成明确授权的实际安装及网络验证后，才能称该机器已切换成功。

原断联调查中尚未解决的健康探测、网络变化消抖、DNS 恢复失败处理及状态显示问题仍见 [断联调查](diagnosis-2026-09-25.md)。本轮增强服务生命周期，不把它等同于所有断联原因已经修复。
