# WgSense v39

## 测速

- 上行的全程曲线、peak、cv 改用接收端数据。原来取的是发送端写进发送缓冲的量，在 Wi-Fi 上比实际到达的更抖，峰值还可能虚高。同一次测量，发送端 cv 30–58%，接收端 9–12%。
- 目标是 App 自己起的 iperf3 服务端时，测速中实时回传服务端每 0.1 秒的区间数据。
- 服务端不是 App 起的（比如 WG peer），测速中先显示发送端，测完用 `--get-server-output` 带回的区间换掉曲线；区间长度以服务端为准，默认 1 秒。
- 拿不到接收端数据（比如公网 HTTP 测速）时用发送端。
- 上行读数下方的 `[src]` 和全程曲线的图例标明本次数据来源，来源也随结果存入历史。
- 下行本来就是接收端数据，取数方式不变。
- 「测法」抽屉里的 iperf3 命令同步更新。

支持 Apple Silicon Mac、macOS 26 或更新。下载 `WgSense-macOS.dmg`，将 App 拖入「应用程序」替换旧版。本版未改动后台服务，直接替换 App 即可。仍采用临时签名，尚无 Apple Developer ID 签名与公证。本版在本机构建打包后直接发布。

验证范围：
- 本机 Release 构建与安装包检查；README 检查通过。
- Mac 走 Wi-Fi 测 BPI-R4，App 实跑 3 次，上行来源均为接收端，下行 996–1008M。
- 不受控服务端与公网 HTTP 两条回退路径各实跑 1 次，来源标注正确。
- 上行 cv 这轮只部分达到 4–10% 的目标：App 实跑 11–22%，脚本实跑 7.7–12.2%。其中 22% 那次是测试中途速率从约 600M 升到约 1080M。这轮没有在关 AWDL、贴近路由器的基线条件下复测。
- 曲线上 0.1 秒的单点仍可能高于同期平均（实测到过 1323M），未确认是否超过当时的链路能力；peak 按 1 秒窗口计算，不受单点影响。
- 未实测：实时回传中途断开后退回发送端的路径；`[src]` 单独成行后只做了离线渲染；未跑性能检查。
