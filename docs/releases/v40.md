# WgSense v40

## 导入配置

- 修复新机器导入 `.conf` 后连不上。后台服务只读当前配置 `default.conf`，导入却只保存成 `名字.conf`，没点「切换」就会找不到配置。
- 还没有当前配置时，导入或向导新建的第一份配置自动启用。已有当前配置时不会被替换，换配置仍用「切换」。
- 后台服务连接时，如果没有当前配置且只有一份配置，就直接用它。已经导入过的机器升级后不用重新导入。
- 有多份配置但都没选用时，报错说明要去点「切换」；一份都没有时，提示先导入。
- 修复新机器上导入后配置显示为空。后台服务以 root 创建配置目录，App 写不进去，错误被忽略；后台服务代写的文件 App 又读不了，编辑页显示空白，「切换」也失败。
- 后台服务启动时把配置目录和 `.conf` 交还给登录用户，代写的文件归目录属主。已中招的机器升级后台服务后自动恢复。
- App 直接写失败时交给后台服务，读不到时向后台服务取；两边都失败才报错，不再静默忽略。
- 配置是空的或缺少 PrivateKey、[Peer] 时，连接立即说明原因，不再等 15 秒后报握手失败。

## 分流隧道

- 分流配置（AllowedIPs 不含 `0.0.0.0/0`）不再用外网探测判断隧道健康。探测目标不经隧道，访问不到时会误判失效，反复重启隧道。
- 分流隧道改看自身状态：持续发包、完全收不到回包、握手超过 180 秒，才算失效。没有流量的空闲隧道不算失效。
- 全局隧道的探测方式不变。

支持 Apple Silicon Mac、macOS 26 或更新。下载 `WgSense-macOS.dmg`，将 App 拖入「应用程序」替换旧版。本版改动了后台服务。更新后请在 App 内先点「停止」断开 VPN，再点「守护」，App 会升级并重启后台服务。仍采用临时签名，尚无 Apple Developer ID 签名与公证。本版在本机构建打包后直接发布。

验证范围：
- 本机 Release 构建与安装包检查；README 检查通过；后台服务 Go 测试全部通过，新增配置选择和分流健康判断的测试。
- 用一份真实分流配置走新的配置选择逻辑，解析和路由规划正确；同一份配置的私钥在外网实测握手成功，能访问对端局域网。
- 用独立用户目录模拟 root 创建配置目录，验证目录和文件能交还给登录用户。
- 未实测：新机器上从导入到连接的完整 App 流程；分流隧道失效后自动重启的实机路径。
