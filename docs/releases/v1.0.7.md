# WgSense v1.0.7

安全修复：全局隧道连着时，任何流量都不再绕开 WireGuard；隧道接管了什么、哪些不走隧道，全部在界面上看得见、改得了。

## 更新内容

- **修复 IPv6 绕开隧道**：此前隧道只有 IPv4 地址时会直接放弃 IPv6 路由，外出网络的公网 IPv6 仍从 Wi-Fi/有线直出；出站拦截又放行国内 IPv6，于是国内 IPv6 流量全部不经过隧道，且界面和网关上都看不到。实际后果之一：微信选中一个不可达的腾讯 IPv6 地址，发图一直转圈。
- **隧道 IPv6：有就用，没有就不用**（全局隧道，即 `AllowedIPs` 含 `0.0.0.0/0` 或 `::/0`）：
  - 连上后公网 IPv6 先拦截：IPv6 连接立即失败，程序马上改用 IPv4 走隧道，不会卡到超时。
  - 同时经隧道探测 IPv6 能否出网。服务器有 IPv6 出口就把公网 IPv6 切进隧道，没有就保持拦截；之后每 5 分钟复查，两个方向都自动切换，不用重连。
  - 本机零配置：WireGuard 不下发地址，隧道 IPv6 按「前缀 + 隧道 IPv4」推出（默认 `fd77:6773::` + `10.66.66.3`）。配置里已写 IPv6 地址时直接使用。
  - 切换路由时先装更细的临时拦截兜底，切换瞬间也不会漏到物理网卡。
  - 断开隧道时路由随之删除；后台服务被强制结束后的残留，下次启动时自动清理。
- **隧道锁定**（出站拦截新开关，默认开）：全局隧道连着时，物理网卡只放行局域网和 WG 服务器。程序绑定物理网卡直连、或走路由表没覆盖到的路径，都绕不开隧道。隧道一断开立即恢复原有拦截规则。被拦下的包会计数显示。
- **概览新增「隧道覆盖」**：一眼看到 IPv6 当前是走隧道还是已拦截（隧道地址、上次/下次探测时间）、隧道锁定是否生效与拦下了多少包、DNS 是否经隧道，以及每一条不走隧道的路径（WG 服务器、当前局域网、未接管的 DNS）和原因。
- **设置新增「隧道 IPv6」**：模式（自动 / 始终拦截）、地址前缀、探测地址都可查看和修改；模式与探测地址立即生效，前缀下次连接生效。
- 修正出站拦截说明里「WG 连着时不受影响」的不准确描述。

## 服务器开 IPv6 时要做的

本机自动识别，只需服务器按同一约定配置：WG 接口加 `<前缀><服务器隧道 IPv4>/96`（默认如 `fd77:6773::10.66.66.1/96`），每个 peer 放行 `<前缀><该 peer 隧道 IPv4>/128`，并为该网段开 IPv6 转发与出口地址转换（NAT66）。

## 安装与更新

官方安装包支持 **Apple Silicon（M 系列）Mac，macOS 26 或更新**。下载 `WgSense-macOS.dmg`，将 App 拖入「应用程序」。`SHA256SUMS.txt` 提供下载文件的校验值。

本版改动了后台服务。更新后请在 App 内先点「停止」断开 VPN，再点「守护」，App 会升级并重启后台服务。

本版仍采用临时签名，尚无 Apple Developer ID 签名与公证。首次打开方式与完整入门见 [使用指南](https://github.com/Zichao-xu/WgSense#开始使用)。

## 验证与已知边界

- 在真实外部网络（Wi-Fi 有公网 IPv6、服务器仅 IPv4）以正式服务实测：连接 10 秒内恢复；IPv6 连接 26 毫秒内立即失败（修复前停在 SYN_SENT 约 4 秒超时）；经隧道访问国内正常；局域网可达；隧道锁定在连接后生效、断开后立即解除并清除全部 IPv6 路由，重连后重新生效。
- 界面实测：「隧道覆盖」显示真实状态；在设置里切换 IPv6 模式，后台即时生效。
- 以 root 在真实 utun 上测试：拦截 → 隧道 → 拦截的路由切换、探测主机路由用后即删、链路本地不受影响。
- 探测与切换、设置校验与保存、锁定规则、拦截计数有单元测试。
- 「服务器有 IPv6 → 自动切进隧道」因服务器尚无 IPv6，仅在模拟环境验证。
- 在这台机器上，绑定物理网卡的程序在路由层已出不去，隧道锁定实测尚未拦到包；它作为另一道保险存在。
- 隧道未建立时（如重连空档）按原有出站拦截规则直连国内，这是「有就用，没有就不用」的取舍，概览会明确显示。
