# WgSense v1.0.7

安全修复：全局隧道下，IPv6 流量不再绕开 WireGuard 从物理网卡直出。

## 更新内容

- **修复 IPv6 绕开隧道**：配置写了 `AllowedIPs = 0.0.0.0/0, ::/0`，但隧道只有 IPv4 地址时，此前会直接放弃 IPv6 路由，公网 IPv6 仍从 Wi-Fi/有线直出；出站拦截又放行国内 IPv6，于是国内 IPv6 流量全部不经过隧道。实际后果之一：微信选中一个不可达的腾讯 IPv6 地址，发图一直转圈，且在网关上完全看不到这条连接。
  - 现在这种情况下会把全部公网 IPv6（`::/1`、`8000::/1`）设为拒绝路由，IPv6 连接立即失败，程序马上退回 IPv4 走隧道，不会卡到超时。
  - 链路本地与局域网 IPv6 路由更具体，不受影响；隧道本身配置了 IPv6 地址时，IPv6 照常走隧道。
  - 断开隧道时拒绝路由随之删除；后台服务被强制结束后残留的拒绝路由，下次启动时自动清理。
- 出站拦截、受信任网络判断、断线自愈逻辑均未改变。

## 安装与更新

官方安装包支持 **Apple Silicon（M 系列）Mac，macOS 26 或更新**。下载 `WgSense-macOS.dmg`，将 App 拖入「应用程序」。`SHA256SUMS.txt` 提供下载文件的校验值。

本版改动了后台服务。更新后请在 App 内先点「停止」断开 VPN，再点「守护」，App 会升级并重启后台服务。

本版仍采用临时签名，尚无 Apple Developer ID 签名与公证。首次打开方式与完整入门见 [使用指南](https://github.com/Zichao-xu/WgSense#开始使用)。

## 验证与已知边界

- 在真实外部网络（Wi-Fi 有公网 IPv6、隧道仅 IPv4）实测：加拒绝路由前，到腾讯 IPv6 地址的连接停在 SYN_SENT 约 4 秒超时；加后 5 毫秒内立即失败，双栈程序退回 IPv4 经隧道访问正常。
- 拒绝路由生效后观察 90 秒，物理网卡上放行国内地址的出站规则命中为 0，没有其他直出流量。
- 拒绝路由的生成条件（仅 IPv4 隧道 + `::/0`；双栈隧道；分流配置）有单元测试。
