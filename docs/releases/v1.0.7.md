# WgSense v1.0.7

安全修复：全局隧道下，IPv6 不再绕开 WireGuard 从物理网卡直出；隧道 IPv6 有就用、没有就不用，全程自动。

## 更新内容

- **修复 IPv6 绕开隧道**：此前隧道只有 IPv4 地址时会直接放弃 IPv6 路由，外出网络的公网 IPv6 仍从 Wi-Fi/有线直出；出站拦截又放行国内 IPv6，于是国内 IPv6 流量全部不经过隧道。实际后果之一：微信选中一个不可达的腾讯 IPv6 地址，发图一直转圈，且在网关上完全看不到这条连接。
- **隧道 IPv6 自动适配**（全局隧道，即 `AllowedIPs` 含 `0.0.0.0/0` 或 `::/0`）：
  - 连上后公网 IPv6 先指向拒绝路由：IPv6 连接立即失败，程序马上退回 IPv4 进隧道，不会卡到超时。
  - 同时经隧道探测 IPv6 能否出网。服务器有 IPv6 出口就把公网 IPv6 切进隧道；没有就保持拒绝。之后每 5 分钟复查，两个方向都会自动切换，不用重连。
  - 本机无需任何配置：隧道 IPv6 地址按约定从隧道 IPv4 推出，`10.66.66.3` → `fd77:6773::10.66.66.3/96`。配置里已写 IPv6 地址时直接使用。
  - 切换路由时先装更细的临时拒绝路由兜底，切换瞬间也不会漏到物理网卡。
  - 链路本地与局域网 IPv6 不受影响；分流配置不接管 IPv6。
  - 断开隧道时这些路由随之删除；后台服务被强制结束后的残留，下次启动时自动清理。
- 出站拦截、受信任网络判断、断线自愈逻辑均未改变。

## 服务器开 IPv6 时要做的

本机自动识别，只需服务器按同一约定配置：WG 接口加 `fd77:6773::<服务器隧道 IPv4>/96`（如 `fd77:6773::10.66.66.1/96`），每个 peer 放行 `fd77:6773::<该 peer 隧道 IPv4>/128`，并为该网段开 IPv6 转发与出口地址转换（NAT66）。

## 安装与更新

官方安装包支持 **Apple Silicon（M 系列）Mac，macOS 26 或更新**。下载 `WgSense-macOS.dmg`，将 App 拖入「应用程序」。`SHA256SUMS.txt` 提供下载文件的校验值。

本版改动了后台服务。更新后请在 App 内先点「停止」断开 VPN，再点「守护」，App 会升级并重启后台服务。

本版仍采用临时签名，尚无 Apple Developer ID 签名与公证。首次打开方式与完整入门见 [使用指南](https://github.com/Zichao-xu/WgSense#开始使用)。

## 验证与已知边界

- 在真实外部网络（Wi-Fi 有公网 IPv6、服务器仅 IPv4）实测：加拒绝路由前，到腾讯 IPv6 地址的连接停在 SYN_SENT 约 4 秒超时；加后 5 毫秒内立即失败，程序退回 IPv4 经隧道正常。拒绝期间观察 90 秒，物理网卡上放行国内地址的出站规则命中为 0。
- 以 root 在真实 utun 上测试：拒绝 → 隧道 → 拒绝的路由切换、探测主机路由用后即删、链路本地不受影响、断开后路由全部删除。
- 探测与切换逻辑、地址推导、全局/分流判断有单元测试。
- 「服务器有 IPv6 → 自动切进隧道」这一路径因服务器尚无 IPv6，仅在模拟环境验证。
- 探测目标为阿里、腾讯、Google 的公共 DNS（TCP 53），任一连通即算有 IPv6。
