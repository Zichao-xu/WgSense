# 测速台（Speed Lab）设计规格

状态：设计中，未开工（2026-10-26）。

起因：2026-10-24 在 op 上测宽带，先后踩了三个坑——测成了"本机↔op 隧道"、op 自身流量被 OpenClash 带去日本、WAN 口掉成 100M。
测速台要把这条排障链路做成一键可复现，并推广到任意两端。

## 1. 定位

一个 AIO 测量台：**任意两端 × 任意路径 × 任意引擎**，结果自动归因到"哪一段是瓶颈"。
入口两个：概览磁贴（`TileKind.speedtest`，代号 `SPD`）+ 侧栏页面（`SidebarTab.speedtest`）。同一个引擎，同一次测量，切页不中断。

## 2. 测量模型

一次测量 = 执行端 A + 路径 B + 目标 C + 引擎 + 参数。

| 维度 | 取值 |
|---|---|
| A 执行端 | 本机 · op · 局域网主机(NAS/Win) · WG peer(有 SSH 的) · 自定义 SSH 主机 |
| B 路径 | 直连(物理网卡+真 DNS) · 经 WG(utun) · 经代理节点(mihomo 端口+指定节点) |
| C 目标 | 公网源(自动选源) · 名册内任一端点 · 自定义(URL / LibreSpeed / iperf3 host:port) |

端点名册：本机、op、`wg show` 读出的 peer、局域网设备、公网源、自定义；新 peer 自动出现。
组合合法性自动判定，不合法的灰掉并写原因（自己测自己；受信任网络下 VPN 必断，"经 WG"不可用）。

## 3. 引擎

| 引擎 | 测什么 | 备注 |
|---|---|---|
| 吞吐 · HTTP | 宽带上下行 | 多源多线程；速率读网口计数器；上传单条长连接（消除重建连接造成的下沉） |
| 吞吐 · iperf3 TCP | 两端之间上下行/双向 | 并发、时长、端口、反向、双向 |
| 吞吐 · 单流 vs 多流 | 单连接上限 | 同目标连测 P=1 与 P=N，差距大 = 单连接受限（代理/hy2/拥塞控制问题） |
| UDP · iperf3 | 丢包、抖动、乱序 | 指定目标带宽阶梯加压，找出开始丢包的带宽 |
| 延迟 | 空载 RTT、负载 RTT | 测吞吐时并行 ping，给出 bufferbloat 评级（A–F） |
| MTU | 路径 MTU | DF 二分探测；WG 场景对比隧道 MTU，报 MTU 黑洞 |
| DNS | 解析耗时、是否被劫持 | 系统 DNS vs 真 DNS；识别 fake-ip(198.18/15) |
| 路径 | 逐跳延迟/丢包 | 精简 mtr：只在"体检"或手动展开时跑，默认收起 |

## 4. 全链路体检（核心增值）

一键分段测量，画成接线图，每段标速率/延迟/协商速率，**最慢段标红并给出一句结论**：

```
本机 ─(Wi-Fi 协商/实测)─ op ─(WAN 协商/实测)─ 公网
  └──────────(WG 隧道实测)──────────┘
```

- 每端读物理链路协商速率（Mac Wi-Fi 速率/有线速率、op WAN、NAS 网卡），**协商速率 < 套餐/对端 = 头号嫌疑**（本次的百兆口）。
- 结论模板举例：「瓶颈：op WAN 口协商 100M（网线/水晶头）」「瓶颈：本机 Wi-Fi 协商 144M」「宽带正常，隧道慢 → 看 WG/对端上行」。
- 出口核验：出口 IP/运营商/是否经代理，防止"测成代理"。

## 5. 结果、历史、基线

- 结果：稳定值(中位数)、峰值、平顶判定(=套餐限速)、下沉段标注不计入。
- 历史：本机 JSON（App 支持目录），按"线路"（执行端 / 路径 / 目标）分组；点阵时间轴。每条记录附当时的测法。
- 基线：每条线路取近 N 次中位数为基线，低于基线 30% 标出「比平时慢」。
- 定时测速：默认关闭；可设凌晨低峰、仅轻量（延迟+单流 5s），避免占带宽。
- 导出：复制文本 / 导出 PNG 报告（含接线图）——对外远程支持时给客户看。

## 6. 泛化

- **能力探测**（首次连接缓存，网络变化失效）：OS/架构、curl、iperf3、chroot、默认路由网卡、DNS 是否劫持、是否有 OpenClash。据此选测法，不按机器名写死。
- **iperf3 自动部署**：App 自带静态 iperf3（linux-arm64 / linux-amd64 / windows-amd64），缺则 scp 到对端临时目录，sha256 校验，测完删除；对端用 `iperf3 -s -1` 一次性起服务。
- **平台**：OpenWrt/Linux(busybox sh)、macOS、Windows(PowerShell over SSH)。速率读取各一份适配，上层共用。
- **源清单**：配置文件可增删；开测前 1–2s 并行探测挑可用源；失效自动跳过，台账写明实际用源。
- **端口**：5201 被占自动顺延；op 上加锁文件，同一时刻只允许一个测量。

## 7. 安全与礼貌

- 占带宽提示：公网测速前显示"将占满宽带约 N 秒、预计 X MB"。
- 计费网络：本机在热点/个人热点时，公网测速需二次确认并显示流量预估。
- 清理：脚本 `trap` + 硬超时；临时 iperf3 服务端、chroot 挂载、上传文件测完必清；App 退出/SSH 断开也能清。
- 防火墙联动：WgSense 出站拦截对物理网卡只放行国内——公网源只选国内；"经代理"走 mihomo 不受影响。
- 测速期间暂停 WgSense 自身健康巡检的"断连判定"，避免大流量下误判重连。

## 8. 呈现（2026-10-27 定稿）

视觉定稿：[`docs/speedlab/design-final.webp`](speedlab/design-final.webp)（GPT 出图，adams 拍板）。
动作参照：《记忆管理局》剧中 UI 动效（本地 `~/Downloads/记忆管理局UI_拆分/01_驾驶舱HUD.mp4`，他人作品，只量动作、不进仓库）。

**落地时对定稿的修正**
- 这是 App 内一页：去掉标题栏、标签页、SPEED LAB 标题、角落代号和版本号等无含义装饰。
- 同一信息只出现一次：保留 MEASUREMENT PIPELINE（RUNNER → NIC → STREAMS ×n → EXIT → SRC），右上改为「选源」面板（候选源试跑结果 keep / drop），不再重复画拓扑。
- 左下只放本机网口（if / link / mtu / util），右下只放判断（每个方向的瓶颈 LINK / UPSTREAM / —、headroom）。
- 不用弧线；灰阶，颜色只给异常（网口降速、出错）。

**元素 = 真实部件**：两翼 = 下行 / 上行通道（刻度 0–协商速率，楔形长度 = 吞吐）；STREAMS = 并发连接数，断线重连只在对应那一根上轻标；RTT 面板直方图 = 真实 ping 采样；判断由数据得出：稳态 ≥ 协商速率 90% → LINK，平顶但未到 → UPSTREAM。

**动作规格**（01/07 段逐帧量得，24fps）
- 平时静止，“有数据才动”：每个事件（阶段切换、采样到达、源结果、重连）触发一段固定短动作。
- 底座常驻（模式块、阶段条、START）；模式切换 = 横幅全宽 1 帧 → 2 帧收成标签块，文字 0 → ⅓ → ⅔ → 1。
- 模块进场：预兆虚影 2 帧 → 1 帧到位；两翼 3 帧射出；子元素每 3 帧一批。
- 读数：字鼓 2 帧滚到新值；楔形亮部 2 帧减速到位，不回弹。

## 8.1 旧版呈现方案（已被定稿取代）

页面（自上而下，骨架恒定、只往里填数）：

1. 线路条：A 执行端 ▸ B 路径 ▸ C 目标。选项只来自「发现」（探测本机、代理后端里的 SSH 主机及其 WG peer、测速源列表）或「添加」，初始为空、不内置任何场景；名字只用用户起的或设备自报的主机名。B 列执行端实际探测到的网卡与「系统路由」。
2. 接线条：A ─ B → C 三个选择器
3. 双表盘：平方根刻度、满刻度随协商速率；克莱因蓝指针（全页唯一动态蓝）；峰值保持刻度；平顶弧段；降速时外圈告警色
4. 台账四格：链路协商 · 出口 · 源/对端 · 阶段
5. 抽屉（默认收起）：参数（时长/端口/并发/单位 Mbps↔MB/s/协议/方向/UDP 带宽）、全程曲线、延迟/丢包、体检接线图、历史

磁贴三尺寸：小=上次结果；中=迷你双表盘；大=迷你表盘+最近用过的 3 条线路直接开测。
菜单栏：测速进行中盾牌旁显示细进度刻度，结束消失。

动效：指针阻尼、读数滚动、测完曲线收拢一次弹簧；只随事件动，尊重减少动态效果。

## 9. 性能

- 执行端每秒回传一行 JSON；SSH `ControlMaster` 复用连接。
- App：后台线程解析；指针交给 Core Animation，每秒只设目标值；刻度静态底图；仅窗口可见时渲染（`WgWindowVisibility`）；空闲零轮询零连接。
- 不改 Go 守护进程：全部在 App 侧，走预览切换流程交付。

## 10. 分期

- **v1**：引擎(HTTP/iperf3 TCP/延迟)、A=本机+op、B=直连+WG、C=公网+有 SSH 的 peer、自动部署 iperf3、表盘页+磁贴、历史。
- **v2**：全链路体检、UDP、单流 vs 多流、MTU、DNS、基线告警、导出报告。
- **v3**：经代理节点、自定义 SSH 主机、Windows 执行端、定时测速、精简 mtr。

## 测法（v1.0.9 起）

一次测速里每个影响结果的决定都在「测法」抽屉里摊开：取值可改、改过的标记、可逐项恢复出厂，并写出每一步在执行端实际跑的命令。执行端脚本 `speedlab.sh` 只管怎么做、不带任何取值，缺参直接报错；开跑时冻结当次测法并随结果存入历史。iperf3 的速率来源可选「iperf3 自报」或「网卡计数」。
